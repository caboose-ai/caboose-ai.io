caboose-ai.io

The lab at the end of the train — a self-hosted playground for things that probably shouldn't be on the internet, carefully put on the internet.

What is this?

A single machine in a home office, rebuilt from a clean slate into a small Kubernetes lab. Everything you can reach under this domain runs there — no cloud compute, no rented servers.

How traffic gets here

you→ Cloudflare edge→ tunnel→ traefik→ k3s pod

The box dials out to Cloudflare and keeps that tunnel open; requests ride back down it. There are no forwarded ports, no inbound firewall holes, and the origin IP isn't in DNS. The only thing listening on the machine's network edge is SSH, from the LAN.

The stack

k3s (single-node Kubernetes) · traefik ingress · cloudflared tunnel connectors · plain YAML manifests, no Helm charts in anger yet. Deployed and wired up with Claude Code.

Game servers

Both of these sit at zero replicas when nobody is playing — a game server idling all week is the one workload on this box that would actually be expensive. Ask and it's up in about a minute.

Minecraft — mc.caboose-ai.io. Fabric survival on the current release, whitelist only. Ask for a spot, then add a server with the address mc.caboose-ai.io and join; an SRV record carries the port, so there is nothing to append and nothing to install. On the home LAN, use 192.168.50.42 instead.

Palworld — pw.caboose-ai.io:58417. Password-gated; ask for the password. Join from the in-game Join Multiplayer Game box by IP, address and port together. On the home LAN, 192.168.50.42:8211.

Unlike this page, the game traffic doesn't ride the Cloudflare tunnel — Cloudflare's free plan won't proxy arbitrary TCP or UDP, so both run through a playit.gg relay instead. Still no forwarded ports, still no origin IP in DNS.
